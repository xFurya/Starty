# Фигурное катание — всё о проекте

Документ для переезда и для того, кто возьмёт проект впервые. Здесь: что это, из чего состоит,
как выкладывается, где что лежит, какие договорённости с владельцем и что не проверено.
Секретов здесь нет — только места, где они лежат.

Состояние на 22.10.2026: Android 1.0.41 (сборка 42); iPhone — через SideStore; Windows/macOS собираются в CI.
Актуальная версия и история — `app/pubspec.yaml`, `tools/released.tsv`. Правила работы и открытые задачи для
нового ассистента — `AGENTS.md`.

## 1. Что это

Календарь стартов по фигурному катанию, сезон 2026/27: российские турниры ФФККР и международные
сегменты, где выступают россияне или белорусы. Время везде московское. Приложение на Android,
iPhone (через SideStore), Windows и macOS; ICS-лента для системного календаря; сайт-страница
скачивания. Интерфейс на русском, дизайн «Лёд».

- Владелец: `-fuR1x` / `Furya`. Пакет `ru.furya.starty`, название продукта — ровно «Фигурное катание».
- Репозиторий: `xFurya/Starty` (ветка `main`). Сайт: `https://xfurya.github.io/Starty/` (GitHub Pages
  из ветки `gh-pages`, её собирает и публикует `update.yml`).

## 2. Из чего состоит

```
scraper/   сборщик расписания на Python (без внешних зависимостей, кроме pdftotext и Pillow)
data/      names.json (имена латиницей → по-русски), facts.json (кэш «примечательного»)
site/      всё, что публикуется: data/events.json, calendar.ics, e/*.ics, photos/, app/ (apk, ipa, json), index.html
app/       Flutter-приложение (Android, iOS, Windows, macOS) + плагин starty_alerts (только Android)
tools/     release.sh (выпуск), publish.sh (первая выкладка в новый репозиторий), released.tsv (выданные номера),
           windows/starty.iss (установщик Windows, Inno Setup)
.github/workflows/  update, live, app-ios, app-desktop
```

### 2.1. Данные (scraper/)

Запуск: `python3 -m scraper.build` (полный, минуты) и `python3 -m scraper.live` (быстрый, секунды).

Источники:
- ФФККР (`fsr.py`): российские турниры уровня МС и КМС, сборная и её фото.
- ISU (`isu.py`): расписание и заявки через открытый `front-api.isu.org`, оглавление — RSC isu-skating.com.
- Табло Swiss Timing (`swisstiming.py`): `index.htm`, `SEGnnn.htm` (стартовый лист → протокол),
  `CATnnnRS.htm` (итог вида), PDF «Start List with Times» (время выхода), PDF
  «JudgesDetailsperSkater» (судейские оценки по каждому). Один формат у ISU, челленджеров и ФФККР.
  У ФФКМ оценки — ссылка «Оценки судей (pdf)» на `…_Scores.pdf` («ДЕТАЛИЗАЦИЯ СУДЕЙСКИХ ОЦЕНОК»); один файл
  бывает у двух сегментов (мужской и женский КП), поэтому заголовок PDF сверяется с категорией и сегментом.
- Golden Skate (`goldenskate.py`): прочие международные турниры.
- Статистика ISU `isuresults.com/isujsstat/` (`facts.py`): мировые рекорды, лучшие оценки сезона, личные рекорды.
- Справочник спортсменов (`people.py`) для поиска в фильтре и уведомлениях: россияне от КМС и выше —
  заявки всех всероссийских стартов ФФККР за этот и прошлый сезон (категории без «разряда»); иностранцы —
  все, у кого есть оценка на турнире ISU за два сезона (`sb<сезон>/sbts<вид><сегмент>.htm`). Разобранные
  протоколы копятся в `data/people.json` (первый сбор долгий, дальше — только новые турниры).
  Фото — сборная ФФККР, портреты ISU (заявки и общий список `front-api.isu.org/skaters/merged-list`),
  Викиданные (люди с номером ISU P2694 и фото P18; к Викимедиа — с честным User-Agent, размер 500).

Выход — `site/data/events.json`: `events[]` (один сегмент = одно событие: `id, tid, tournament, kind
(women/men/pairs/dance), level (senior/junior), seg (КП/ПП/РТ/ПТ), start/end (ISO, МСК), venue, intl,
broadcast, ours[], athletes[], src`), у прошедших — `podium` (тройка сегмента), `total` (тройка турнира,
только у последнего сегмента вида), `provisional` (протокол ещё не утверждён), `facts[]` («примечательное»),
`live{}` (адреса табло — приложение читает их само во время старта; `live.basis` — judges, time или null:
окончательность сегмента), `proto` (имя файла протокола турнира или null), плюс `upcoming[]` (турниры без
сегментов), `photos{}`, `watchlist[]`, `roster[]`, `people[]` (`{n, c, k}`: имя, страна, виды `wmpd`),
`sources{}`.

Региональные федерации (ФФКМ — Москва, СООО «ФФКК» — Самарская область): у их стартов и турниров
`upcoming[]` есть `tier: "regional"` и `region: "Москва" | "Самарская область"`; у федеральных поля
`tier` нет. Региональные старты в `calendar.ics` не попадают (файл статичный), по файлу на старт — есть.
Старт без времени не добавляется. В `sources{}` статус региона — `"ok"` или текст причины.

Состав и отслеживаемые: у каждого события `field[]` — весь состав (`name, nation, no, warmup, time,
place, final`). В данные идут **все** сегменты турниров, а не только с россиянами. `ours[]` сервер
по-прежнему пишет (россияне и белорусы; на российских стартах — `watchlist` из `config.json`) — для
старых версий приложения и для общего календаря. Новое приложение строит `ours` само
(`Start.withFollow`): на международных — россияне, белорусы и отслеживаемые, на российских — отслеживаемые.
Отслеживаемых выбирает человек (Настройки → Отслеживаемые): отдельно «все россияне» и «все белорусы» на международных и любые спортсмены; пока не выбирал — `watchlist`. Правило уведомлений «Только с отслеживаемыми» и «Выход отслеживаемых» работают по этому же списку. У заявок турниров без расписания `ours_nation` — страна россиян и белорусов.
Международный старт без россиян и отслеживаемых в ленту и уведомления по умолчанию не попадает —
только когда в фильтре выбран его турнир или спортсмен (`Filters.explicit`, `Start.shown`).

Правила, которые легко сломать:
- **Кого считаем «своими»** (`scraper/config.json → ours_codes`): `RUS`, `AIN2` (нейтральные россияне),
  `BLR`, `AIN1` (белорусы), `AIN`. С 10.10.2026 белорусы — наравне с россиянами. В интерфейсе —
  в карточке участники подписываются динамически: «Россияне», «Белорусы» или «Россияне и белорусы»; слова «наши» нигде нет. Белорусов в «Примечательном» называем только когда они
  выиграли («Победа белоруса») или входят в интересную череду («Первые 6 мест — россияне и белорусы»,
  «Весь пьедестал — …»): `facts.lead_facts`.
- **Табло во время старта**: на странице сегмента бывает несколько таблиц с шапкой «Pl.» (сам сегмент и общий
  зачёт). Берётся таблица с TES/PCS, один человек — одна строка (`swisstiming._result_rows`, `live.dart`).
  Проверка: `python3 -m unittest scraper.test_swisstiming`.
- **Имена**: латиница → по-русски из словаря `data/names.json`; белорусы и прочие, кого там нет, — вручную в
  `scraper/config.json → latin_names` (иначе остаются латиницей).
- **Сегмент прошёл**, когда протокол на табло и время старта позади; **окончательный** — только когда
  у сегмента выложены и подтверждены судейские оценки (JudgesDetails или PDF ФФКМ с совпавшим заголовком).
  До этого тройка помечена «промежуточные»; табло без оценок остаётся промежуточным (режим «окончательный
  по времени» — `config.json → final_by_time`, выключен). Одиночки ФФКМ: строки и тройка — из PDF
  оценок, если они сходятся со стартовым листом или итогом вида (`podium_from_judges_pdf`).
- **Протоколы** (`protocols.py`): файл турнира `site/data/protocols/<tid с _ вместо :>.json` — сегменты,
  строки, детали оценок (элементы, GOE, компоненты, сбавки), бригада и итог вида; `status.json` рядом —
  когда табло читалось. Только на gh-pages (в main не коммитится): workflow перед сбором берёт прежние
  файлы оттуда (`tools/protocols-from-pages.sh`). Файл, не прошедший проверку, не пишется — остаётся
  последний удачный; окончательный сегмент не откатывается. Быстрый сбор — не больше 12 запросов к табло
  за прогон. Контракт и состояния — `scraper/protocols.py` (докстринг) и проект протокола §2.
- **Если источник не ответил**, берутся данные прошлого сбора. Если будущих стартов стало вдвое
  меньше — данные не обновляются (защита от поломки источника).
- **«Примечательное»** считается один раз, когда есть судейские оценки, и запоминается в
  `data/facts.json` по адресу PDF. Поменялись правила — поднять `VERSION` в `scraper/results.py`:
  всё пересчитается. Сравнение с мировой статистикой — только на международных стартах.
- **Правила сезона 2026/27**: в произвольной программе убрали один каскад, поэтому все прежние
  рекорды баллов — исторические (в тексте так и пишется). Сравнивать новые оценки со старыми
  рекордами по сумме и ПП осторожно.
- Фото: `photos.py` режет миниатюры 256 px на своём сайте (`site/photos`) по найденному лицу (OpenCV,
  модель `scraper/face_yunet.onnx`; без OpenCV — по пропорциям); при смене нарезки поднять `CUT`.

### 2.2. Автоматика (GitHub Actions)

| Файл | Когда | Что делает |
|---|---|---|
| `update.yml` | 09:00 и 15:00 МСК, вручную, пуш в `main` (кроме данных) | полный сбор → коммит данных в `main` → публикация `site/` в `gh-pages` |
| `live.yml` | раз в час (`:17`), вручную, пуск из `update.yml`, правка сборщика | задание живёт до 5 ч 50 мин и крутит `tools/live-loop.sh`: пока идёт, вот-вот начнётся (до 75 минут) или недавно закончился (90 минут) старт — раз в ~4 минуты быстрый сбор, при изменениях коммит в `main` и публикация; нет стартов — выход за секунды. Раз за запуск добираются старые неокончательные итоги (до 24 ч). Cron у GitHub неточный (запуски «каждые 10 минут» приходили раз в несколько часов), поэтому цикл сам держит окно, а `update.yml` в конце будит `live.yml`, если идут старты |
| `app-ios.yml` | пуш в `app/**` | `.ipa` без подписи на macOS-раннере → `site/app/Starty.ipa`, `sidestore.json`, `version.json`; номер сборки уже выложен — пропуск |
| `app-desktop.yml` | пуш, в котором менялся `site/app/latest.json` (то есть выпуск) | Windows: установщик `starty-setup-<версия>.exe` (Inno Setup есть на раннере) и zip; macOS: zip и `.dmg` → релиз `app-v<версия>` во вкладке Releases (плюс копии под постоянными именами `Starty-windows-setup.exe`, `Starty-macos.dmg` — на них ссылается сайт) → записи `windows`/`macos` в `latest.json`; ручной запуск — пробная сборка без выкладки |

Секретов нет, кроме встроенного `GITHUB_TOKEN`. Нужны права записи у токена (`contents: write`, `actions: write`)
и Pages из ветки `gh-pages`. `update.yml` и `app-*` делят очередь `update`/`app-*`; пуши в `main` подряд
отменяют друг друга — публикация сайта может запоздать на несколько минут. `live.yml` — в своей группе `live`
(следующий запуск ждёт конца текущего), полный сбор его не ждёт.

Публикация `gh-pages` двумя заданиями: общая блокировка — ветка `pages-lock` (`tools/pages-lock.sh`, создать
ветку, которой нет, может только один; брошенная старше 15 минут снимается). Под замком только короткий хвост:
`update.yml` — сохранить данные, слить свежие протоколы с `gh-pages` (`scraper.pages_merge`: файл с более
поздним `built` побеждает), опубликовать; `live.yml` — на каждый проход свежий `main` и свежие протоколы,
сбор, коммит, публикация. Публикует `tools/publish-pages.sh`: один коммит и сравнивающая запись
(`--force-with-lease`), история `gh-pages` не растёт.

### 2.3. Приложение (app/)

Flutter 3.47.7, Dart ^3.13.5. Важное по файлам `app/lib/`:
- `main.dart` — тема «Лёд» (`Palette`), вкладки (лента, месяц, настройки) со свайпом, неподвижная область строки состояния.
- `data.dart` — модель (`Start`, `Placing`, `Fact`, `LiveSrc`, `Schedule`), копия расписания на устройстве, `Prefs`; код страны хранится и у участников списка `ours[]`.
- `state.dart` — состояние; опрос табло раз в минуту, пока приложение на экране (`startLive`/`pollLive`).
- `live.dart` — разбор табло Swiss Timing на стороне приложения (тот же, что в `swisstiming.py`).
- `reminders.dart` — правила уведомлений (`NotifyRules`) и планировщик. Текст уведомления не менять без
  просьбы владельца: заголовок `ЧЧ:ММ · сегмент`, тело — турнир · россияне/белорусы со временем · трансляция.
- `updater.dart`, `desktop_updater.dart`, `update.dart` — самообновление (см. §4).
- `views.dart`, `sheets.dart`, `ui.dart`, `settings.dart` — экраны, карточка старта, виджеты, настройки. На международных результатах `AIN2` показывается как `RUS`, `AIN1` как `BLR`. В карточке свайп двигает целую поверхность вместе с фоном и содержимым и закрывает её только после намеренного протяжного жеста от верхней позиции. Тот же свайп у листов фильтра и выбора спортсменов (`showSwipeSheet`); закрытие свайпом — без сохранения. Фильтр, выбор спортсменов и правила уведомлений применяются только по кнопке («Показать …», «Сохранить»); правила уведомлений — отдельное окно (`_NotifyPage`), главный экран настроек — только переключатель, итог и переходы. Виды подписываются под уровень (`kindLabel`): женщины и мужчины — взрослые, девушки и юноши — юниоры, оба уровня — «Женщины (девушки)».
- `background.dart` — фоновое обновление: Android раз в 3 часа (WorkManager), iPhone (BGAppRefresh); на ПК
  фоновых задач нет, обновление раз в 3 часа, пока приложение открыто.

Платформы:
- **Android**: нативный `Updater.kt` (самообновление) и плагин `app/packages/starty_alerts` (точные будильники,
  без цифры на иконке). У каждого уведомления три момента: `at` — показать, `hold` — до него закреплено
  (старт — до конца, спортсмен — пока не откатал: место в протоколе или время выхода + 8 мин), `end` —
  убрать (спортсмен — через 15 мин после выхода, если включено «Убирать после выхода»). Закреплённое
  раз в 5 минут обновляется на месте без звука: One UI показывает в строке состояния лишь три
  «последних» значка, и без этого уведомление видно только на экране блокировки. `setSilent` не
  использовать — он кладёт уведомление в общую группу «silent».
- **iPhone**: те же Dart-уведомления через `flutter_local_notifications`, фон — `workmanager`.
- **Windows**: установщик Inno Setup (`tools/windows/starty.iss`): одному пользователю, без прав администратора,
  в `%LOCALAPPDATA%\Programs\Figure Skating`; ярлык в «Пуске» (на рабочем столе — по галочке), удаление — в
  «Приложениях» Windows. Мастер на русском. `AppId` установщика не менять: по нему находится прежняя установка.
  Ярлык и процесс несут один AppUserModelID `ru.furya.starty` (тот же, что у тостов): `main.cpp` ставит его при
  запуске, чтобы закреплённое на панели задач совпадало с ярлыком. `main.cpp` держит мьютекс
  `ru.furya.starty.app` — установщик ждёт закрытия приложения, удаление просит закрыть. Внутри — `starty.exe` и
  библиотеки среды Visual C++. Zip с той же папкой остаётся в выпуске для старых версий (§4).
  Тосты системы без пакета MSIX нельзя отменить, приложение помнит поставленные. Протокол — в браузере системы.
- **macOS**: `Starty.app` с подписью ad-hoc, песочница выключена (иначе не заменить себя при обновлении).
  Первая установка — `.dmg` (Starty.app и ярлык на «Программы»), обновления — zip.
  Первый запуск (подпись ad-hoc): «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть»
  (на macOS 15 и новее правая кнопка → «Открыть» больше не помогает).

### 2.4. Синхронизация настроек (app/lib/sync.dart, tools/sync/)

Один документ на человека: отслеживаемые, правила уведомлений и исключения, фильтр ленты, «Завершённые»,
тема, значок и региональные федерации. Два способа войти:
- **аккаунт** — почта и пароль (Supabase Auth). Таблица `user_settings`, политика RLS: строку видит и меняет
  только её владелец; функции `save_settings` / `load_settings` вызываются с токеном входа;
- **код синхронизации** — 16 знаков без похожих символов, входа нет. На сервере лежит только SHA-256 от
  `starty-sync:<код>`, сам код не хранится. Функции `save_settings_by_code` / `load_settings_by_code` —
  `security definer`, доступны анонимно только через них.

**Один аккаунт — два входа.** Настройки одни, входов в них может быть два: почта и код. Привязать можно из любого
состояния (страница «Аккаунт»):
- вошли по коду → «Привязать почту»: вход или регистрация, затем `link_code` для текущего кода, устройство
  переключается на почту; перед привязкой несохранённые правки уходят под кодом, настройки не сбрасываются;
- вошли по почте → «Создать код» (создаёт и сразу привязывает; новая привязка заменяет прежнюю) или ввод чужого
  кода («Привязать»). Код на сервере хранится хэшем, поэтому само значение показывается только на том устройстве,
  которое его создало или вводило (`sync.linked`); на остальных — «Код привязан» (`has_code_link`).
Сервер: таблица `code_links` (`code_hash` → `user_id`; код привязан к одному аккаунту, у аккаунта один код).
`link_code(code_hash)` — только вошедшему по почте, `security definer`. Документы сливаются по правилу «побеждает более
позднее `updated_at`» (при равенстве — документ аккаунта); время победившего документа не меняется, так что устройства,
уже видевшие его, ничего не скачивают заново. После привязки документ живёт только в `user_settings`, строка
`code_settings` кода удаляется; `save_settings_by_code` / `load_settings_by_code` привязанного кода работают с
документом аккаунта. Ошибки: `code_taken` («Код уже привязан к другому аккаунту»), `bad_code`, `not_signed_in`.
Если схема сервера старая и `link_code` отвечает 404, приложение пишет «Обновите схему сервера», остаётся на прежнем
входе и ничего не сбрасывает; обычный вход по почте или коду от схемы не зависит. Устройства на старом коде после
замены привязки не получают общих настроек: код становится пустым и заводит свой документ заново.

Слияние — документ целиком. Побеждает последнее сохранение на сервере: время его ставит сервер
(`updated_at = clock_timestamp()`, save-функции его возвращают), часы устройств в порядке не участвуют.
Устройство помнит время последнего сохранения, которое видело (`baseAt`), и есть ли у него несохранённая
правка (`pending`). С правкой документ уходит на сервер, даже если там уже новее: правки на двух устройствах
одновременно — одна затирает другую. Без правки устройство берёт серверный документ, если он новее.
Список отслеживаемых — тоже целиком. Вход в существующие настройки (аккаунт или чужой код) сначала берёт
серверные: прежние правки этого устройства не отправляются (`SyncController.preferRemote`). Сверка — при
запуске, при возврате в приложение и через 3 с после правки. Правка во время сверки не теряется: она остаётся
отмеченной и уйдёт следующей сверкой.

Выход из аккаунта (`AppState.signOutSync`) и отключение кода (`AppState.disconnectSync`) сбрасывают настройки
этого устройства к значениям по умолчанию (`Prefs.resetSynced` и служебные ключи `sync.*`), после подтверждения
в настройках (только заголовок и кнопки). Бэкенд отключается раньше сброса, поэтому сброс на сервер не уходит;
сервер и другие устройства не меняются. Следующий вход в пустой аккаунт отправляет дефолтные настройки.

Сервер задаётся сборкой: `--dart-define=SUPABASE_URL=… --dart-define=SUPABASE_ANON=…`. Без них раздел
«Аккаунт» в настройках честно пишет «Аккаунты в этой сборке недоступны».

Что нужно владельцу, чтобы включить:
1. Создать проект Supabase; в SQL Editor выполнить `tools/sync/schema.sql`. Если схему уже выполняли раньше,
   выполнить файл снова: save-функции пересоздаются и теперь возвращают время сохранения. Без этого приложение
   покажет «Сервер не сообщил время сохранения». Привязка кода к аккаунту (`link_code`, `has_code_link`,
   `code_links`) тоже появляется только после повторного выполнения файла.
2. В Authentication включить вход по почте. Если подтверждение почты включено, регистрация отвечает
   «Письмо для подтверждения отправлено» — это подсказка, а не ошибка.
3. Передать URL и anon-ключ в сборку. **Открыто:** сборки в `app-android.yml`, `app-ios.yml` и
   `app-desktop.yml` пока не передают эти значения — нужно добавить `--dart-define` и секреты репозитория.

Тесты: `app/test/sync_test.dart` (слияние, код, аккаунт, два устройства, сбои, вход в чужие настройки),
`app/test/sync_link_test.dart` (привязка почты к коду и кода к аккаунту, ошибки, старая схема).

## 3. Выпуск новой версии

Основной путь — через CI (`.github/workflows/app-android.yml`): поднять `version:` в `app/pubspec.yaml`
(например `1.0.21+22`), написать описание первой строкой в `tools/release_note.txt`, закоммитить и запушить в `main`.
Воркфлоу сам скачает ключ подписи из приватного `xFurya/-VPN` (секрет `VPN_PAT`), соберёт и подпишет APK, выложит
его на сайт, допишет `tools/released.tsv` и `latest.json`, затем запустит Windows/macOS (`app-desktop.yml`).
Запасной путь — локально: `bash tools/release.sh 1.0.21 "Описание."` (нужны `app/android/key.properties`,
Flutter и Android SDK), потом коммит и пуш.

- **Номер версии выдаётся один раз** (`tools/released.tsv`): обновление ставится по номеру сборки, два разных
  файла под одним номером — второй телефон не увидит никогда. CI и скрипт пропускают уже выложенный номер.
  Не запускать оба пути на одну версию.
- Описание — одна короткая строка без чисел и разбора причин: его читают в окне обновления.
- После пуша сами соберутся iPhone и ПК-сборки (§2.2). `latest.json` перезаписывается целиком, записи
  `windows`/`macos` потом добавляет `app-desktop.yml` с тем же номером; пока их нет, ПК обновление не предлагает.
- Подпись Android проверяется сборкой: отпечаток обязан остаться
  `84f451ebac960ae69f8bf06949be9ad8abe86571cc475a36249790851fb0e7d1` (SHA-256), иначе обновление не встанет поверх.

## 4. Самообновление

Все платформы читают `https://xfurya.github.io/Starty/app/latest.json`:
`{version, code, notes, at, android:{file,size,sha256}, windows:{code,url,size,sha256,setup:{url,size,sha256}},
macos:{code,url,size,sha256,dmg:{url,size,sha256}}}`. `url/size/sha256` у ПК — всегда zip: по ним обновляются и
версии, которые не знают установщика; `setup` — установщик Windows, `dmg` — образ для первой установки на Mac
(приложение его не читает).
- **Android** (`Updater.kt`): раз в час и при открытии; докачка по Range (до 5 повторов, 60 с без данных); сверка
  размера, sha256, пакета, versionCode и подписи; установка через PackageInstaller, когда приложение свёрнуто.
  Файл лежит во внутренней папке приложения, одна версия за раз.
- **Windows/macOS** (`desktop_updater.dart`): то же скачивание и сверка; установка при закрытии приложения или по
  кнопке «Обновить сейчас».
  Windows: есть `windows.setup` — установщик запускается тихо (`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART
  /CLOSEAPPLICATIONS /RELAUNCH=1|0`), ждёт выхода приложения по мьютексу, ставит и (по кнопке) открывает заново;
  нет — как раньше, zip и скрипт замены файлов. Копия из старого zip при запуске передаёт управление установленной
  (`handOffToInstalled`), если та уже есть; сама она обновляется установщиком и
  так переезжает в настоящую установку; её папка остаётся как была (со своей, уже старой, версией).
  macOS: zip — короткий скрипт ждёт выхода, заменяет `Starty.app` и (по кнопке) запускает заново.
- **iPhone**: обновления приходят через SideStore (`site/app/sidestore.json`); приложение лишь сообщает о новой версии (`version.json`).

## 5. Где лежат секреты

- **Ключ подписи Android**: в приватном репозитории `xFurya/-VPN`, ветка `ccr-0ea504fd-67m7mq`,
  папка `starty/keystore/` (`starty-release.jks` и `key.properties` с паролями). В публичный `Starty` ключ
  **не класть никогда**. Для сборки скопировать `key.properties` в `app/android/key.properties` и поправить в нём
  путь `storeFile`. Потеря ключа = обновления Android перестанут вставать, пользователям придётся ставить заново.
  Сделайте свою копию вне GitHub.
- iPhone: подписи нет — SideStore подписывает Apple ID пользователя. Windows: без подписи. macOS: ad-hoc.
- Токены: только встроенный `GITHUB_TOKEN` воркфлоу.

## 6. Как перенести проект

1. Создать новый репозиторий и из этой папки выполнить `bash tools/publish.sh https://github.com/<владелец>/<имя>.git`
   (кладёт содержимое в `main`, `site/` в `gh-pages`). Включить Pages из `gh-pages`, права воркфлоу — «чтение и запись».
2. Заменить адрес сайта и репозитория везде, где он зашит: `app/lib/data.dart` (`dataUrl`), `app/lib/update.dart`,
   `app/lib/desktop_updater.dart`, `app/lib/settings.dart` (ссылки подписки), `app/android/app/src/main/kotlin/ru/furya/starty/Updater.kt`,
   `tools/release.sh`, `site/index.html`, `site/app/*.json`, `scraper/ics.py`, `README.md`, `.github/workflows/*` (имена, при необходимости).
   Поиск: `grep -rn "xfurya\|xFurya" . --exclude-dir=.git`.
3. **Установленные приложения ходят за обновлениями по старому адресу.** Чтобы они переехали, старый сайт должен
   жить, пока все не обновятся: выпустить с нового места версию, но положить её `latest.json`/APK и на старый адрес
   (или последним выпуском со старого адреса отдать сборку, где зашит новый).
4. Подпись Android оставить прежней (§5), иначе обновление поверх не встанет.
5. SideStore-источник — новый `sourceURL`; у пользователей iPhone придётся добавить источник заново.

## 7. Договорённости с владельцем

- Тексты интерфейса: коротко, безлично, без разговорного тона. Правило: «интерфейс не имеет права показывать то,
  чего нет, и молчать о том, что есть»; нет данных — прочерк, а не правдоподобное число.
- Названия: продукт — «Фигурное катание»; владелец — `-fuR1x` или `Furya`; никаких «наши» — «россияне». Белорусов
  «просто так» не пишем (владелец, 10.10.2026), только победы белорусов и интересные серии.
- «Каскад», а не «связка».
- Флаги стран — по просьбе владельца (16.10.2026; прежний отказ 10.10.2026 был о другом): флаг 3:2 с тонкой
  обводкой и рядом код страны приглушённым цветом — везде, где показывается страна (тройка, итог турнира, протокол,
  судьи, поиск). Флаги вшиты (flag-icons, MIT, `app/assets/flags`), только страны ISU; AIN2 — Россия, AIN1 — Беларусь;
  флага нет (регион, простой AIN, TPE) — только код.
- Без разделительной точки «·» (владелец, 16.10.2026): несколько фактов в строку через точку не пишем — каждый факт
  на своём месте (строкой, колонкой, меткой, надзаголовком).
- Итоги и примечательное должны появляться сразу, не дожидаясь сбора на сервере.
- Выпуски: Android — APK на сайте, iPhone — SideStore, Windows — установщик, macOS — `.dmg` (оба во вкладке
  Releases, рядом zip для самообновления).
- Не создавать pull request без просьбы. Разработка и пуши — в `main` репозитория `Starty`.

## 8. Что проверено, а что нет

Проверено: сборки всех четырёх платформ в CI, анализ и тесты (`flutter test`), разбор табло и судейских
протоколов на настоящих страницах Мемориала Дениса Тена, вёрстка в браузере (Playwright).
Не проверено на настоящих устройствах: самообновление и уведомления на Android и iPhone в рабочем виде,
всё на Windows и macOS (запуск, тосты, замена файлов при обновлении, установщик и тихое обновление им, `.dmg`),
опрос табло в приложении во время идущего старта.
Известные ограничения: на Windows нельзя снять
поставленные тосты; в веб-версии нет опроса табло (браузер не пускает на чужой сайт).

## 9. Полезные команды

```
cd app && flutter pub get && flutter analyze && flutter test
python3 -m scraper.build          # полный сбор → site/ и data/
python3 -m scraper.live --check   # есть ли что обновлять (код выхода 0 — есть)
python3 -m scraper.live --plan    # что делать циклу live: hot | cold | wait <секунд> | none
flutter build web --release --dart-define=DATA_URL=http://127.0.0.1:8790/data/events.json   # стенд для скриншотов
```
Переменные сборки: `--dart-define=BUILD=<номер> --dart-define=VERSION=<x.y.z>`; для скриншотов `NOW=<ISO>`
подменяет «сейчас». Для запуска стенда нужна локаль `ru-RU` (иначе «Incorrect locale information»).

## Значок приложения

Набор вариантов — `tools/icons/variants.json`: «Классический» в трёх цветах (основной значок — «Лёд», id `classic`;
им же становятся значки iPhone, Mac, Windows и веба) и «С сегодняшним числом» в шести. Слои рисует `tools/icons/render.js` (Chromium через playwright: фон, фигуристка, полоса календаря,
числа 1–31 — заливка и белый контур), `tools/icons/make.py` раскладывает их:
- Android: `res/drawable-nodpi/icl_*` (слои), `res/drawable/icf_*` (передний план — layer-list, контур числа
  тонируется), `res/mipmap-anydpi-v26/ic_v_*` (адаптивные), в манифест — `activity-alias` на каждый значок
  (у значка с числом — на каждый день). Сама активность — `.AppActivity`; основной значок — псевдоним с
  прежним именем `.MainActivity`, чтобы не терялись ярлыки на главном экране. Переключает `AppIcons.kt`:
  когда приложение уходит с экрана (выключение псевдонима, через который оно запущено, на части лаунчеров
  закрывает его) и в полночь (точный будильник) — число всегда сегодняшнее. Ограничение лаунчеров: One UI
  при смене псевдонима может убрать значок с главного экрана (в меню приложений он остаётся).
- iPhone: альтернативные значки `Assets.xcassets/skate_*.appiconset`, настройка сборки
  `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES`; значков с числом нет — iOS спрашивает при каждой смене значка.
- Компьютер: значок окна, панели задач (Windows) и Дока (macOS), пока приложение открыто; рисует
  `app_icon.dart` теми же слоями (`assets/icon/layers`), число меняется в полночь.
Перерисовать: `node tools/icons/render.js <папка>` и `python3 tools/icons/make.py <папка>`.
